# 账本有鬼 · AuditQuest

> 大数据审计课程个人作业 ｜ 提交日期 2026-11-15

一套单文件练习网页：30 道审计单选题，作答结束后按六章正确率生成一份销售与收款循环的审计报告。配套交付一份 IMA 知识库、七张离线知识卡片和十份过程文档。

## 一、运行

双击 `index.html`，用 Chrome 内核浏览器打开即可，无需安装或联网。浏览器若限制本地脚本，在目录内执行 `python3 -m http.server 8000`，访问 `http://localhost:8000`。

报告页 `报告/审计报告.html` 也可单独打开。不带参数时显示演示样本（满分视角，37 笔异常全部列出）；从成绩页点「生成我的审计报告」，或带 `?r=&c=&n=` 参数进入时，显示与成绩对应的版本。`r` 为总分，`c` 为六章正确率，`n` 为姓名，均可省略。

## 三、页面功能

### 闯关页

流程为：创建身份 → 案卷墙 → 答题 → 章节结算 → 总成绩与结案证书 → 错题本。身份四选一（审计助理、IT 审计员、内控专员、数据分析师）。案卷墙六张卡片对应五章加综合卷，综合卷需前五章完成后解锁；某章全对会盖「已结案」章。

题目共 30 道单选，题干写成具体审计现场，问在该场合下的处理方式。章节范围：

| 章 | 范围 |
|---|---|
| 第一章 准则与底稿 | CSA 编号与规范对象、国家审计准则制定主体、审计阶段归属 |
| 第二章 风险与重要性 | 重要性调整、舞弊三角、控制测试与实质性程序、风险评估程序 |
| 第三章 证据与程序 | 函证例外、监盘责任、分析程序异常、充分性与适当性 |
| 第四章 IT 与数据 | ITGC 与应用控制、CISA 五域权重、全量筛查与抽样、取数完整性核对 |
| 第五章 舞弊与操守 | 舞弊责任、收入确认舞弊假定、独立性、收入截止性 |
| 综合卷 | 5 道跨章题 |

答题即时判分并给出解析、来源编号与可信度；「本地提示」是预先写入的规则文本。总分按 `正确数 ÷ 30 × 100` 四舍五入，0–59 入门、60–84 达标、85–100 熟练。最高分、名字与身份存 `localStorage`，结案证书带分数、等级、日期，可用 `window.print()` 打印。错题自动收集进错题本。

### 审计报告

八节按「定性 → 举证 → 程序」排列。抬头为意见章与三格数字（分数、查出异常、范围受限）；KPI 五格给数据规模：收入 28,285 万、发票 4,860 张、命中 37 笔、涉及金额 1,096.8 万、抽样覆盖 1.23%，点任一项展开计算口径。

| 节 | 内容 |
|---|---|
| 01 月度趋势 | 12 月 3,960 万（月均 1.68 倍），末五天 1,240 万，次年 1 月退回 620 万 |
| 02 客户集中度 | 前五名 52.4%，前两名接近 30% |
| 03 账龄 | 应提 490 万，账面 412 万，缺口 78 万 |
| 04 Benford | 首位「1」高出期望 8.3 个百分点 |
| 05 异常清单 | 7 类 37 笔按金额排序，点条形筛选下方表格 |
| 06 样本清单 | 12 笔逐笔追合同号、出库单、签收日期，可标记状态 |
| 07 程序建议 | 截止性、关联方、拆单、函证四条线，按最弱两章高亮 |
| 08 复核事项 | 按章折叠，列出该章检查点与对应卡片 |

意见类型按总分映射：

| 总分 | 意见 |
|---|---|
| ≥ 85 | 无保留 |
| 70–84 | 无保留 + 强调事项段 |
| 55–69 | 保留 |
| < 55 | 无法表示意见 |

不设置否定意见。低分在此代表检查范围受限，而非已取得充分证据后判定存在重大且广泛的错报，判定依据见 `知识库/03_审计意见类型_判定对照表.md`。

两种模式下检出量不同：演示样本列出全部 37 笔；「我的报告」按 `该类异常笔数 × 对应章正确率` 计算，未查出的部分标为「没碰」。该换算为页面自定规则，用于把答题结果映射到异常清单，不作为审计方法。

报告数据为课程练习构造的模拟集，客户名称虚构，页面顶部与页脚各标注一次。所有合计数由页面内 `DATA` 数组现算，可逐项复算。

### 两页衔接

两页共用一条 sharecode，连接点有三处：各屏顶栏的「闯关 ｜ 报告」切换按钮；成绩页将分数与六章正确率拼进 URL 的报告出口；报告顶栏带原 sharecode 的回链。报告页 `?ch=4` / `?ch=5` 深链可直达对应章节，未填名字时先停在创建身份页。

## 四、实现说明

两个页面都是单文件 HTML，CSS、SVG、JavaScript 全内联。不带 CDN、外部字体、`fetch`、API Key、Service Worker 或外部图片；四名角色与场景插画为内联 SVG。断网可运行。

首页采用 3 列 × 2 行斜切分格，格间 13 px 米白缝配 2.4 px 黑边。动效包括分格入场、标题逐字弹入、角色浮动、切屏过渡、按钮位移与进度条变化，在 `prefers-reduced-motion` 下降级为即时呈现。900 px 与 500 px 两档取消斜切以避免文字被裁。

`file://` 协议下两个文件不共享 `localStorage`，成绩因此通过 URL 参数 `r / c / n` 传递；刷新报告页会退回演示样本。

## 六、题目来源与声明

每题标注 S1–S13 来源编号与可信度。S1–S8 支撑 30 道题，S9–S13 用于知识卡片与报告口径。写进题库的均核到原文：审计署第 33 号公告在官网未检索到原文，整条剔除；CPA 2026 年《审计》大纲附件 PDF 未逐字比对，只引模块层级，标「中」。S13 仅核公式与常用阈值，标「中」。

本项目由本人独立完成，界面、题目、评分规则、报告页与证书的代码和文案均为原创。AI 用于需求拆解、来源检索建议、代码骨架、文档结构与四名角色 SVG 路径起草；事实性内容（准则编号、域权重、施行日期）回官方页面核对，所有数字人工复核。知识卡片为二次整理的笔记，不整段摘录条文。三份课内实验报告已脱敏转写，交付物不含身份信息。

## 七、已知限制

- 本题库为框架识记型练习，不覆盖需要职业判断的复杂情境。
- 无后端、账号体系与数据库，成绩只存本机浏览器；刷新报告页会退回演示样本。
- 仅在 Chrome 内核验证，未做移动端真机测试。
- 报告的 37 笔异常为人为注入，命中率不代表真实审计发现率；筛查规则覆盖 7 类常见形态，不是完整审计程序。
- 意见类型只映射四类；CPA 大纲附件与 S13 的核对程度见上一节。
