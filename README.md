# 大数据审计 · 个人作业｜账本有鬼 AuditQuest

> 2026-11-15 提交 ｜ 计算机审计专业 ｜ 个人独立新建

这是一个答题网页。三十道审计题，答完按你的正确率生成一份审计报告；报告里那 4,860 张发票能查出几笔，取决于你六章各答成什么样。题目只考审计框架，不考会计分录。

除此之外还有一套 IMA 知识库、七张可以离线查的本地卡片，和十月做预研时留下的记录。

## 一、打开顺序

1. 双击 `index.html`。断网也能跑。建个身份，进案卷墙，答题。
2. 读完这份 README，知道链接在哪、边界在哪。

## 三、做了什么

页面是单文件 `index.html`，94 KB，CSS、SVG、JavaScript 全内联。整个文件不带 CDN、不带外部字体，不写 `fetch`，没有 API Key，也没有 Service Worker。四名角色是内联 SVG 画的，一张外部图片都没引。

**首页**是 3 列 × 2 行的斜切拼贴。格子之间是 13 px 米白缝加 2.4 px 黑边（参考站做的是黑框白缝，我一开始压成了一条黑缝，整块发闷，后来拆回两层）。四格角色放大到被格边裁掉一部分，外圈套一圈实心白贴纸边，中央格是红黄放射底加白雾标题，下半压一枚手盖印章。字体正文走苹方或微软雅黑，标题用 `--disp` 变量逐级回退，字号用 `clamp()` 跟着屏宽缩放。底子是牛皮纸加网点，粗黑描边，硬投影不带模糊，卡片轻微歪着。

动效有六组：分格依次入场、标题逐字弹入、角色上下浮动、切屏淡入上移、按钮按下位移、进度条过渡。全部在 `prefers-reduced-motion` 下降级成即时呈现。

**案卷墙**是章节地图。六张档案卡，每张上半是手绘场景插画（文件夹、折线加放大镜、天平、显示器、红旗、卷宗加印章），下半是黑底信息条，写章名和主题词，不写题数。左上角圆形徽章旋 −7°，跟主菜单的角色标签同一套语言。综合卷没解锁时插画蒙 52% 黑罩、整体灰度、中央挂一把锁。某章全对，右上角盖一枚红色「已结案」章，一眼能看出哪章真过了。

**流程**是这样走的：

```
主菜单（漫画分格）
  └ 创建身份：名字 + 四选一身份（审计助理 / IT 审计员 / 内控专员 / 数据分析师）
      └ 案卷墙：六张档案卡（五章 + 综合卷），锁态、主题词、已结案红章
          └ 答题：即时判分 + 解析 + 来源标注 + 本地提示
              └ 章节结算：本章正确率 + 等级
                  └ 总成绩：总分 + 六章条形 + 结案证书 + 报告出口，可打印
                      └ 错题本：答错的自动收集，附正确答案与解析
```

**题目**五章 25 题加综合卷 5 题，共 30 道，全是单选。题干都写成具体现场（什么时间、在哪、正在做什么），问的是这个场合你会怎么办。

- 第一章 准则与底稿：CSA 编号与规范对象、国家审计准则谁制定、阶段归属
- 第二章 风险与重要性：重要性能不能改、舞弊三角里的机会、控制测试与实质性程序、风险评估程序的范围
- 第三章 证据与程序：银行存款函证的例外、监盘的责任边界、分析程序发现异常之后、充分性与适当性
- 第四章 IT 与数据：ITGC 与应用控制、CISA 五域权重、全量筛查和抽样、取数前的完整性核对
- 第五章 舞弊与操守：舞弊责任归谁、收入确认的舞弊假定、独立性怎么处理、收入截止性
- 综合卷：跨章 5 题，前五章各过一遍才解锁，考的是能不能把零散点串成一个案子

**算分**：30 题等权，总分 = 正确数 ÷ 30 × 100，四舍五入。0–59 入门，60–84 达标，85–100 熟练。25 题对是 83 分，26 题对是 87 分。前五章随便进，综合卷要前五章都过一遍才开。结案证书带姓名、分数、等级、日期和印章，跟成绩单一起打印。`localStorage` 记最高分、名字和身份，下次打开自动带出。打印用 `window.print()` 加独立样式，白底黑字，没引 PDF 库。

### 另一页：跟着答卷走的审计报告

`报告/审计报告.html`，77 KB，同样单文件零依赖。这一页是闯关打完之后那份报告，不是一块固定的仪表盘。同一份 4,860 张发票，你六章答成什么样，决定报告里能查出几笔。

顶栏一个分段按钮切两种模式。没答过题点进来是「演示样本」，满分视角，37 笔异常全在，意见是无保留，右上角盖一枚「演示样本」章，用来对照。从成绩页点「生成我的审计报告」进来，或者带 `?r=&c=&n=` 进来，就是「我的报告」：该章对应的那类异常只查出「笔数 × 该章正确率」那么多，剩下的标成「没碰」。

意见类型按总分映射，不随手挑：

| 总分 | 意见 | 报告抬头 |
|---|---|---|
| ≥ 85 | 无保留 | 该查的都查了，异常在可接受范围内 |
| 70–84 | 无保留 + 强调事项段 | 结论没问题，但年末开票这一块要单独提一句 |
| 55–69 | 保留 | 有几块没查透，结论只对查过的部分成立 |
| < 55 | 无法表示意见 | 范围受限太严重，不发表结论 |

不做否定意见。出否定意见的前提是证据拿够了、错报重大且广泛；这里分低的原因是没查出来，属于范围受限，不是查清了再否定。这条写在报告页脚和 `知识库/03_审计意见类型_判定对照表.md` 里。

八节的顺序是先定性、再举证、后给程序。抬头是意见章加三格数字，分数、查出异常、范围受限各一格。KPI 五格给规模：收入 28,285 万、发票 4,860 张、命中 37 笔、涉及金额 1,096.8 万、抽样覆盖 1.23%，点哪一格都会展开这个数怎么算出来的。

中间四节是数据分析。01 看月度趋势，12 月 3,960 万，是月均的 1.68 倍，末五天就做了 1,240 万，到次年 1 月退回 620 万。02 看客户集中度，前五名占 52.4%，前两名接近 30%。03 看账龄，应提 490 万，账上只提了 412 万，缺口 78 万。04 是 Benford，首位「1」的出现频率比期望高出 8.3 个百分点。

05 到 08 是往下落的具体动作。异常清单把 7 类 37 笔按金额排开，点条形能筛下面的表；样本清单挑 12 笔逐笔追合同号、出库单和签收日期，可以标「划掉」或「转程序」；程序建议给四条线（截止性、关联方、拆单、函证），按你最弱的两章高亮先做哪条；最后是复核事项，按章折叠，告诉你这章查什么、该读哪张卡片。

同一组数，分数不同看到的重点也不同。分数低，12 月那根柱子旁边直接写着这块没查；分数高，37 笔逐笔都有下落。

数据是课程练习构造的模拟集，页面顶部提示条和页脚各标了一次，不对应任何真实客户。所有合计数由页面里 `DATA` 数组现算，能逐项复算。

### 两页怎么配合

一个考「知不知道」，一个考「查没查出来」。两个页面共用一个站点、一条 sharecode，接缝只留了三处。所有屏的顶栏都带一个「闯关 ｜ 报告」分段按钮，哪一屏都能直接跳。成绩页出来之后有一整行的出口，把分数和六章正确率拼进 URL。报告顶栏的回链落回 `index.html`，带着原来的 sharecode，会话不丢。

原来还有两条：案卷墙下面压了一段解说，章节结算页多一个跳转按钮，都删了。案卷墙那一步的动作是挑案子，压一段字，人会先读字再点卡；结算页的下一步只该有一个。报告只在成绩出来之后推一次，那时候才真有人想知道自己漏了什么。

深链 `?ch=4` / `?ch=5` 保留着，报告里第 4、5 章各是一个入口，点进去直接开那一章；没填过名字就先停在创建身份页，提示「填个名字，直接进第 4 章」。

## 六、个人声明

这个作业从选题、出题、写页面到测完，一个人做，2026-11-15 一天之内完成。界面、30 道题、评分规则、报告页、结案证书的代码和文案都是自己写的。

每道题标了来源编号（S1–S13）和可信度。写进去的都是核到原文的：审计署第 33 号公告在官网没搜到原文，整条剔掉，没拿二手转载凑数；CPA 大纲的附件 PDF 没逐字比对，只引模块层级，标「中」。S1–S8 撑起 30 道题，S9–S13 只用在知识卡片和报告口径上。

页面不联网。不带 CDN、不带外部字体、没有 `fetch`、没有 API Key，断网双击就能跑。答题时的「本地提示」是提前写好的规则文本，不是在线模型在回答。

报告页的数据是构造的模拟集：4,860 张发票、28,285 万收入、37 笔注入的异常，按制造业常见形态设定，不对应任何真实客户。合计数由页面里的 `DATA` 数组现算，能逐项复算。那个「查出几笔」的换算是自己定的——某类异常笔数乘该章正确率，不是行业做法，只是想把答对多少和查出多少接上。

AI 用在需求拆解、来源检索建议、代码骨架和文档结构上。事实性内容（准则编号、域权重、施行日期）一律回官方页面核，所有数字人工核过。四名角色的 SVG 路径由 AI 起草，自己逐条调坐标后内联进源码；没用图片生成模型，也没引外部图片。

知识卡片是二次整理的笔记，不是原文摘录。每条标来源编号，能追到 `题库与官方来源清单.md` 的 S1–S13；表述是自己的话，引条文只引编号和要点。

## 七、哪些地方我没做到

- CPA 2026 年《审计》大纲的附件 PDF，正文没逐字核对，所以第二章相关题目只引大纲的模块层级，不引具体措辞和页码，可信度标「中」。
- 审计署第 33 号公告没在官网检索到原文，来源清单 S7 标的是「不引用、不出题」。
- S13（Nigrini《Benford's Law》2012）没拿到全书，只核了公式和常用阈值，卡片里的判读区间标「中」，不当结论依据。
- IMA 知识库在我个人账号里，外部打不开。所以用条目清单图和清单文档作证；`知识库/` 那七张卡片内容跟 IMA 条目一致，但不是同一份文件。
- 这是框架识记型练习，不构成执业能力测评，也不覆盖需要职业判断的复杂情境。
- 没有后端、没有账号体系、没有数据库，成绩只存本机浏览器。`file://` 下两个文件不共享 `localStorage`（实测：a.html 写的键，b.html 读到 `none`），所以成绩靠 URL 参数传，刷新报告页会退回「演示样本」。这是限制，不是 bug。
- 没做移动端真机测试，只做了响应式布局；浏览器只在 Chrome 内核验过。500 px 和 900 px 两档用无头浏览器截图核过，没有横向溢出。
- 报告里那 37 笔异常是人为注入的，所以「命中率」不代表真实审计的发现率。筛查规则也只覆盖 7 类常见形态，不是完整程序。
- 意见类型只映射四类，不做否定意见，理由在第三节和 `知识库/03` 里写了。
